# espresso cluster

Flux reconciles this tree from `main` with `prune: true`. A moved directory, a
renamed resource or a changed ConfigMap is a live change the moment it is
pushed, so compare `kustomize build` output before and after any refactor and
say in the commit body which resources change.

- `flux-system/` is generated by Flux bootstrap. Leave it alone.
- `apps/<app>/` — one folder per app; `tests/app-shape.sh` defines the required
  shape and holds the exemptions.
- `infrastructure/controllers/` then `infrastructure/configs/` then `apps/`:
  Flux applies them in that order through `dependsOn`.
- `tofu/<stack>/` — OpenTofu stacks run by tofu-controller. Every stack applies
  its plan automatically once pushed; `tests/tofu-approval.sh` pins that policy.
- Scripts shipped to pods live as real files under `apps/<app>/scripts/` and
  reach the cluster through `configMapGenerator`.

## DNS

Two systems own records, split by type:

- **external-dns** owns CNAMEs, declared as `DNSEndpoint` resources pointing at
  `router.asgard.michaelbrusegard.com`. The zone must be listed in
  `domainFilters` under `infrastructure/controllers/external-dns` first.
- **OpenTofu** (`tofu/dns`) owns everything else: MX, TXT, DKIM, MTA-STS.

The lint rules and `tests/` scripts enforce the split.

## Secrets

Encrypted Secret manifests live in `../infra-secrets/gitops/espresso/` and are
