# Engineering collaboration

Use these defaults for engineering work across repositories. Repository-local
instructions and an explicit user request can make them more specific.

## Authorization

Do not create external artifacts, send messages, push, deploy, merge, close, or
delete unless the user authorized that action.

## Michael's writing style

When drafting text that will be posted or sent as Michael:

- Put the point first, then the relevant context and ask or next step.
- Keep the writing concise and natural. Remove filler, canned phrasing, and
  repetition.
- Match Michael's established tone and the surrounding conversation.
- Preserve exact technical details without mimicking incidental mistakes or
  misrepresenting who performed the work.

## Model provenance

Every human-facing artifact written on Michael's behalf must identify the model
that wrote it. This includes PR and issue descriptions, review comments, issue
comments, Slack messages, email, release notes, incident communications, and
similar outbound text. It does not apply to source code, tests, machine-readable
data, ordinary repository documentation, or the agent's chat response to
Michael.

Use the exact model slug exposed by the current runtime. Do not guess, shorten,
normalize, or infer a model name. If the runtime does not expose it, use
`UNKNOWN-MODEL`.

For comments, replies, Slack, email, and other conversational messages, use
this layout exactly:

```md
[actual reply]

---
MODEL-SLUG · responding on behalf of Michael
```

Replace `MODEL-SLUG` and `[actual reply]`; do not include the code fence. Keep
the provenance footer at the very bottom of the message, after the horizontal
rule. Use plain text as shown; do not format it as a heading or emphasize it.

For PR descriptions and other durable authored descriptions, put this as the
final line after a horizontal rule:

```md
---
Generated by MODEL-SLUG using the HARNESS harness.
```

Use the harness's real product name, such as `Codex`, `Claude Code`, or `Pi`.
If a distinct client wraps the harness and its name is known, use this fuller
form:
`Generated by MODEL-SLUG in CLIENT using the HARNESS harness.` Never guess the
client or harness.

Do not remove or rewrite model provenance while editing an existing draft.
Immediately before an external write, verify that the correct provenance form
is present once at the bottom of the artifact.
